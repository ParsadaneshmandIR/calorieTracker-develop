# منابع داده و روش‌شناسی

## اصول

1. **واحد پایه:** همیشه `kcal` (و گرم ماکرو) **در ۱۰۰ گرم بخش خوراکی**. «کالری در هر پرس» هرگز منبع حقیقت نیست.
2. **بدون اسکرپینگ:** فقط API رسمی JSON و CSV بسته‌شده در ریپو.
3. **کش محلی:** USDA و Open Food Facts فقط در جاب/endpoint ادمین فراخوانی می‌شوند. درخواست کاربر از H2/PostgreSQL + Caffeine می‌خواند.
4. **خام در برابر پخته:** غذاهایی که آب جذب می‌کنند (مثل برنج) باید دو ردیف با `state` متفاوت داشته باشند.

## USDA FoodData Central

| مورد | مقدار |
|---|---|
| کاربرد | مواد اولیه خام / Foundation و SR Legacy |
| API | `https://api.nal.usda.gov/fdc/v1` |
| لایسنس | Public domain |
| نگاشت | بر اساس `nutrientId` / نام مادهٔ مغذی، نه اندیس آرایه |
| رد ردیف | اگر `macrosConsistent` شکست بخورد (اختلاف Atwater > ۲۰٪) |

کلید: `USDA_API_KEY` / `usda.api-key` — در مخزن ذخیره نمی‌شود.

## Open Food Facts

| مورد | مقدار |
|---|---|
| کاربرد | محصولات بسته‌بندی‌شده با بارکد |
| API | `GET /api/v2/product/{barcode}.json` |
| لایسنس | ODbL 1.0 (در UI ذکر می‌شود) |
| User-Agent | اجباری: `PersianCalorieTracker/1.0 (contact: …)` |
| نرخ | حداکثر ۱۰ درخواست در دقیقه |
| انرژی | `energy-kcal_100g`؛ در نبود آن `energy-kj_100g / 4.184` |

## CSV غذاهای ایرانی (`data/iranian-foods.csv`)

برآورد دستی از میانگین دستورهای خانگی رایج. ستون `notes` منبع/فرض هر ردیف را ثبت می‌کند.

### فرض روغن و شکر

بسیاری از خورش‌ها و کوکوها به روغن حساس‌اند. مقادیر «میانگین» هستند؛ افزودن یک قاشق روغن (~۱۲۰ kcal) می‌تواند نتیجه را جابه‌جا کند. شکر در چای/قهوه لحاظ نشده است.

### برنج خام در برابر پخته (حیاتی)

| نام | state | kcal/100g تقریبی |
|---|---|---|
| برنج خام | RAW | ≈ ۳۶۰ |
| برنج پخته | COOKED | ≈ ۱۳۰ |

نسبت چگالی انرژی حدود ۲٫۷ به‌خاطر جذب آب است. ادغام این دو ردیف ممنوع است.

### وضعیت (`FoodState`)

- `RAW` — خام / خشک / پوست‌دار قبل از پخت
- `COOKED` — پخته / آب‌پز / سرخ‌شدهٔ آمادهٔ مصرف
- `PACKAGED` — برند/بستهٔ صنعتی (ماست، دوغ، بستنی، …)

### درصد خوراکی (`ediblePortionPct`)

برای اقلامی مثل تخم‌مرغ با پوست، درصد بخش خوراکی اعمال می‌شود:  
`kcal = kcalPer100g × grams × ediblePortionPct / 10_000` (HALF_UP، مقیاس ۱).

## MealEntry و اسنپ‌شات

هنگام افزودن آیتم به وعده، کالری و ماکروها در `MealEntry` ذخیره می‌شوند تا اصلاح بعدی ردیف `Food` تاریخچه را بازنویسی نکند.

## دستور پخت (`Recipe`)

`kcal/100g = Σ(kcal مواد) / totalWeightGrams × 100` — در لحظه محاسبه می‌شود و ذخیره نمی‌گردد.
